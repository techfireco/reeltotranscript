Standard Operating Procedure

Micro Tool Website Factory

Build small, problem-solving tool websites with AI, rank them on Google, and monetize with AdSense — at roughly ₹1,000 per site. Repeat monthly.

The model at a glance

Solve one tiny problem per website. Low competition → easier ranking → organic traffic → ad revenue.

Find micro problem→ Validate keyword→ Build with AI→ On-page SEO→ Deploy free→ Connect .com→ Index & measure→ AdSense
Win-winWorst case, all 12 sites fail — you still have 12 live, deployed projects to show in job interviews. Best case, 1–2 rank and generate passive income you can reinvest.

Phases

01 Research & validation 02 Build with AI 03 SEO & launch prep 04 Deploy, domain & email 05 Index, measure, backlinks 06 Monetize & repeat

Phase 1

Research & validation

Spend real time here. A validated idea decides everything downstream.

1

Find a micro problem

  • Watch your own daily life: anything you Google is a potential tool idea. Save every one in your phone's Notes app and research later.
  • Mine Reddit: search Google for "is there a tool for" site:reddit.com (also try site:quora.com). Each post is someone describing an unsolved problem.
  • Paste long posts into an AI model (Claude, Gemini) and ask it to extract tool ideas.
  • Pick small problems only — big problems mean funded competitors; micro problems mean low competition and a site you can ship in a day to a week.
Never do thisDon't share your ideas publicly or with friends in your field. Every share creates competitors for your exact keyword.
2

Validate the idea before building

  • Find the real main keyword: search your phrasing, then note what ranking sites actually call it (e.g. you search “online scale”, the market says “online ruler”).
  • Check volume in the free Ahrefs Keyword Research Tool. Volume is per-country (US by default) — other countries and languages add more.
  • Audit every competitor on pages 1–3: note every flaw (no dark mode, broken UI, bad mobile layout, missing filters/features, paid-only). Your site must fix all of them.
  • Scan competitor domains: if top rankers don't have the exact keyword in a .com domain, that's a green light for you to take it.
  • Check competitor traffic + growth trend with the free Ahrefs Traffic Checker.
  • Note extra sub-tool ideas from keyword variations (by image, from URL, from PDF…) and plan a multi-language (i18n) version to rank in other countries with less competition.
Monthly volumeDifficultyRecommendation
~100Very easy to rankBest starting point
~1,000MediumThe sweet spot
~10,000ToughOnly after a few wins
Golden keyword signalIf page 1–2 shows irrelevant results — Reddit/Quora posts, Play Store links, PDFs, random blogs — Google has nothing to show. Build there and you can rank very fast.
3

Choose the domain name (don't buy yet)

  • Check availability on Instant Domain Search. Two hard rules: the main keyword must be in the domain, and it must be a .com.
  • Exact .com taken? Use Google autocomplete: add a space before or after your keyword to discover natural modifiers (real…, free…, …ai, a…), then pick an available variant.
  • Sanity-check the modifier keyword's volume too, then lock your name (e.g. fontfinderai.com).
Sequence mattersBuild the website first, buy the domain last. Domains bought in excitement often never get built. Money wasted.
Ranking killerCheap TLDs (.xyz etc.) and free subdomains (pages.dev, workers.dev, vercel.app, netlify.app) don't rank. The ₹1,000/yr .com is the one unavoidable cost.

Phase 2

Build with AI

Prime the agent properly and it ships a premium site instead of AI slop.

4

Prepare the machine & pick the stack

  • Install Git, Node.js, and an editor — VS Code, Antigravity, or Zed.
  • Pick an AI coding agent: Claude Code (subscription) or free options like Antigravity / Opencode. They all work — the process is identical.
  • Stack = Astro JS: server-first, zero JS by default, multi-page, SEO-optimized, and Cloudflare-optimized. Use Next.js only for client-heavy dashboard-style apps.
  • Hosting = Cloudflare Pages for static sites (unlimited free traffic) or Cloudflare Workers for dynamic sites (~100k free requests/day; $5/mo if you ever outgrow it).
Why not Vercel / NetlifyTheir 100 GB free bandwidth ≈ 50k page views. Cross it and the site goes down — and Google derankings from downtime are hard to recover.
5

Prime the AI agent

  • Create a folder named after the domain, cd into it, run the official Astro install command; init in the current directory (.) and say Yes to Git init.
  • Add the Astro extension to your editor.
  • Install the Tailwind 4 docs skill (project scope, symlink is fine) — prevents v3/v4 confusion and wasted tokens.
  • Pull a design.md via getdesign.md (Vercel default; Apple, Figma, BMW etc. also available) — this is what kills gradient-heavy AI slop.
  • Add the Astro Docs MCP server to your agent so it always uses current Astro APIs.
Why this worksSkills + MCP + design.md give the agent a fixed environment: fewer hallucinations, fewer retries, fewer tokens, and a consistent professional look on every site.
6

Build the website

  • Switch the agent to plan mode, then run the website-building prompt with: site name + domain, description, competitor URL, and a request for improvement suggestions.
  • Answer the agent's questions deliberately: keep the tool free, unlimited, no accounts; prefer free APIs/free tiers; accept sensible rate-limit guards; keep the site as static as possible.
  • Ask for a separate page per sub-tool (by image / from URL / from PDF…) — each page ranks for its own keyword.
  • Approve the plan, let it build and self-test (mobile, light/dark mode).
  • Run npm run dev → open localhost:4321 → manually test the core tool, dark mode, and every page.
7

Git discipline (the token saver)

  • Commit before every prompt: Source Control → stage changes (+) → short message → Commit.
  • Bad AI output? Don't ask the AI to undo (wastes tokens) — just Discard Changes to roll back to the last commit.
  • Start every new task in a fresh session (/new) — long sessions burn through usage limits.

Phase 3

SEO & launch prep

Everything here happens before the site ever goes live.

8

Run the on-page SEO prompt

  • Collect supporting keywords from the Ahrefs keyword generator. Skip competitor brand keywords (WhatTheFont, Canva, Adobe…).
  • /new → run the SEO prompt with main + supporting keywords. It handles titles, meta descriptions, OG tags, JSON-LD structured data, and content depth.
  • Speed is already handled: Cloudflare's edge CDN serves from the nearest country.
9

Add FAQ schema

  • Gather real questions: Ahrefs keyword generator → Questions tab, plus Google's People Also Ask (keep expanding to load more; search “what + keyword” if PAA doesn't appear).
  • /new → run the FAQ prompt (one question per line) so FAQs ship as JSON-LD markup — these already rank on Google, so they pull rankings fast.
10

Favicon & logo

  • Pick an icon from an icon library; tune preset, border, rounding (~60), padding 0, shadow none → download PNG.
  • Run it through Real Favicon Generator (site name + short name) → download zip → unzip → copy all files into public/.
  • /new → paste the generated snippet: “favicon images are in the public directory, add favicon support.”
  • Copy the icon's SVG element (Inspect → Copy element) → tell the agent: use this SVG as the site logo; favicon is done, don't touch it.
SVG, not PNGAn SVG logo auto-inverts to white in dark mode. A PNG stays black and breaks the theme.
11

Trust pages & error pages

  • /new → run the required-pages prompt: Privacy Policy, Terms & Conditions, Contact, About. Without these, AdSense will never approve the site.
  • /new → add error pages: 404 (not found) and 500 (server error).
12

robots.txt, sitemap & mobile check

  • Verify localhost:4321/robots.txt exists (the agent usually creates it, with the sitemap URL inside).
  • Sitemaps only generate at build time: npm run build → npm run preview → verify /sitemap-index.xml and /sitemap-0.xml. If missing: “create sitemap.xml, use the Astro Docs MCP.”
  • Mobile check: DevTools → Toggle device → pick a phone → refresh → test everything. If broken: “make the website mobile responsive.”

Phase 4

Deploy, domain & email

Ship it to the world — hosting free, domain paid, email free.

13

Back up code on GitHub (recommended)

  • Install the GitHub CLI: brew install gh (Mac) / winget install GitHub.cli (Windows) / sudo apt install gh (Linux) → gh auth login → GitHub.com → HTTPS → browser login.
  • Create a private repo → confirm branch is main → run the git remote add… and git push commands shown by GitHub.
  • Ongoing: stage → commit → Sync Changes after every finished task.
14

Deploy to Cloudflare

  • Create/log in to a Cloudflare account, then connect the terminal: npx wrangler login → authorize in browser → Y.
  • Ask the agent: “Is this website static or dynamic — Cloudflare Pages or Workers?” Then run the matching deployment prompt (it also adds a deploy script to package.json).
  • Test the temporary *.workers.dev / *.pages.dev URL end to end.
Every future updateCommit → Sync Changes → npm run deploy. That's the whole release process, forever.
15

16

Kill duplicate content

  • Workers: production deployment → Domains → turn off both workers.dev URLs (only after the custom domain is live).
  • Pages: create public/_headers with the 301 redirect rule from yourproject.pages.dev/* to https://yourdomain.com.

Same content on two URLs = duplicate content in Google's eyes = deranking.

17

Free professional email

  • Cloudflare → Email Routing → onboard your domain → Activate (MX, SPF, DKIM, DMARC are configured automatically).
  • Add your Gmail as a destination address and verify it.
  • Add a routing rule: hello@yourdomain.com (or admin@ / contact@) → send to your Gmail.
  • Send a test email and check it arrives (look in spam), then use this address on the Contact page.

Replaces a ₹290–500/month mailbox with ₹0. A Gmail on the contact page looks unprofessional; this doesn't.

Phase 5

Index, measure & backlinks

Tell Google you exist, then track everything.

18

Google Search Console

  • Add your domain as a property (no https prefix).
  • Verify via DNS: choose “Any DNS provider” → copy the TXT value → Cloudflare DNS → Add record → type TXT, name @, paste content → Save → Verify.
  • URL Inspection → enter https://yourdomain.com → Request Indexing. Repeat for any new or significantly updated page.
  • Sitemaps → submit sitemap-index.xml (and sitemap-0.xml as backup).
  • Check the Performance tab weekly: clicks, impressions, and average position per keyword.
Favicon patienceIf your favicon doesn't show in results, do nothing. Google picks it up automatically within ~7 days.
19

Bing Webmaster Tools

  • Get started → Import from Google Search Console — one click brings your sites over.
  • Request indexing for the homepage and submit both sitemaps.

Bing throws random errors — don't stress. Google is the priority; Bing is backup traffic.

20

Google Analytics

  • Create a property → country, category, business objectives → add a Web stream (https is pre-selected; don't retype it).
  • Copy the Google tag (Install manually) → /new → “add this Google Analytics code to the website.”
  • Commit → npm run deploy → verify the tag in View Page Source → Test installation → Confirm.
  • Watch: live users, countries, top pages, and traffic channels (organic vs direct vs video).
21

Backlinks — the compounding trick

  • Interlink your own tool sites, only where a link genuinely helps the user. One ranking site passes link juice to all the others.
  • Pace it: no backlinks for the first month after launch → then one link → next after ~1.5 months → one or two more by month 2.
  • Let organic backlinks accumulate naturally — a genuinely good tool gets cited in blogs on its own.
Link spamAdding many links at once reads as spam and drops rankings (learned the hard way). Slow and related-only wins.

Phase 6

Monetize & repeat

AdSense rewards patience. Apply too early and you burn a review.

22

Apply to AdSense — timing is everything

  • Wait until the site is 1–2 months old AND gets 2–10 organic clicks/day (check GSC → Performance; friends' visits don't count).
  • Sign up with your main personal email + 2-step verification — you get one AdSense account per lifetime (PAN-verified).
  • Sites → New site → enter the domain (no https) → verify via an ads.txt file in public/ (easiest method) → commit → npm run deploy → Verify → Request Review.
  • Rejected for “low value content”? Add genuinely useful content — real detail, real examples, not padding (AI prompt works) → Confirm → Request Review again. Low traffic often triggers this, so waiting also fixes it.
23

Turn on Auto Ads

  • On approval: Ads → Ads by site → copy the entire code block.
  • /new → “This is my Auto Ads AdSense code, please implement it” (it belongs in the <head>).
  • Commit → npm run deploy → AdSense → Auto Ads → Edit → turn ON Auto Ads + auto-optimize → Apply to site.
  • Skip manual placements — Google's auto-optimization outperforms them.

Earnings accumulate in AdSense and hit your bank the month you cross $100. Meaningful revenue starts around 100–200 visitors/day.

24

Repeat ×12

  • Ship at least one site per month (2–4 if time allows). Keep noting new ideas as they appear.
  • Expect failures — the creator's first success was website #8. With this SOP the mistakes are pre-paid; commit to 1–2 years.
  • Reinvest early earnings into more domains to compound output.

Golden rules

Always

  • .com only, main keyword in the domain
  • Build first, buy the domain last
  • Commit before every AI prompt; /new per task
  • Keep sites static wherever possible
  • Fix every flaw you found in competitors
  • 1 year domain, auto-renew off, re-compare prices
  • Wait for organic traffic before AdSense

Never

  • Share your keyword/ideas publicly
  • Use .xyz or free subdomains for ranking
  • Buy multi-year plans or add-ons
  • Add all internal backlinks at once
  • Apply to AdSense in week one
  • Target competitor brand keywords
  • Leave workers.dev / pages.dev duplicates live

Master pre-launch checklist

Run this top to bottom for every single site.

  • Idea validated (volume, competitors, golden signals)
  • .com domain chosen with keyword
  • Agent primed: Tailwind skill, design.md, Astro MCP
  • Site built & tested (npm run dev)
  • On-page SEO prompt done
  • FAQ JSON-LD added
  • Favicon + SVG logo installed
  • Privacy, Terms, Contact, About pages
  • 404 + 500 error pages
  • robots.txt + sitemap verified after build
  • Mobile responsiveness checked
  • Code pushed to private GitHub repo
  • Deployed to Cloudflare Pages/Workers
  • Domain connected (root + www), duplicates disabled
  • Email routing live (hello@domain)
  • GSC verified, indexing requested, sitemaps submitted
  • Bing imported from GSC
  • Google Analytics tag verified
